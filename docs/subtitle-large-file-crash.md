# Subtitle mux assertion crash

The user-authorized Crashlytics console inspection on November 24, 2026 confirmed four fatal events affecting three users on 1.2.1 (121). Expanded frames show IsoTypeWriter.writeUInt32 -> StaticChunkOffsetBox.getContent -> container serialization -> EmbeddedSubtitles.mux -> VideoDownloadService.tryEmbedSubtitles. This identifies a 32-bit MP4 chunk-offset serialization overflow, rather than a text-encoding or subtitle-language error. Original exception messages are sanitized by this app's uncaught-exception handler; RuntimeException is the telemetry wrapper around AssertionError.

DefaultMp4Builder 1.9.56 creates stco tables. When final media offsets exceed 0xffffffff, those offsets require co64 tables. The fix promotes all stco tables in that case, then adds the increase in header size to every media offset, since the builder places moov before mdat. Promoting all tables together also handles a previously smaller track crossing the boundary after header expansion. Small files retain their existing tables. The builder used here emits ordinary unencrypted media tracks and tx3g subtitles, not CENC auxiliary-offset tables.

The mux boundary also translates AssertionError to IOException, retaining the cause. This allows the service's existing subtitle-failure path to delete the incomplete subtitle output and preserve the already downloaded source. Cancellation exceptions and VM errors such as OutOfMemoryError are not swallowed.

Validation: debug compilation and ten targeted JVM tests passed (six subtitle, two AAC, two offset tests). Offset fixtures exercise >4 GiB values without allocating a multi-gigabyte video, all-track header adjustment, repeat validation and the unsigned-32 boundary. Existing subtitle tests compare sample hashes/timings and Chinese/overlapping captions. New boundary tests verify recoverable assertion behavior, unchanged input, cancellation identity and VM-error propagation. No real >4 GiB affected user file was available for end-to-end replay, and the new APK has not been installed on a physical phone or published.

The dashboard also showed a separate OutOfMemoryError in misScaledVideoEditFactor, four fatal events affecting three users in the same seven-day window. That is a distinct issue and is not fixed by the co64 correction. Other visible BadToken issues are outside this MP4 change. No issue status was changed in Firebase.
